01 · Product boundary

מה WIFIGATE Host עושה

What WIFIGATE Host does

שירות server-to-server שמקבל פרטי אורח והזמנה ממערכת מלון, יוצר קישור WIFIGATE מוצפן ותואם־אפליקציה, ומחזיר אותו למשלוח לאורח.

A server-to-server service that accepts guest and reservation data from a hotel system, creates an encrypted app-compatible WIFIGATE link, and returns it for delivery to the guest.

איפיון יעדTarget specification

מקור האירוע

Event source

PMS, Channel Manager, OTA backend או מערכת מלון שולחים אירוע ל־WIFIGATE Host לאחר יצירה או עדכון של הזמנה.

A PMS, Channel Manager, OTA backend or hotel system sends an event to WIFIGATE Host after a reservation is created or updated.

תוצאת השירות

Service outcome

קישור /wifigate-api/?ep=… פרטי ומוגבל בזמן, שניתן לשלוח ב־SMS, אימייל או אפליקציית האירוח.

A private, time-bound /wifigate-api/?ep=… link ready for SMS, email or the hospitality app.

פתיחה בפועל

Actual opening

האורח מייבא את הקישור לאפליקציה; הפתיחה מתבצעת מקומית מול השער ב־BLE המאובטח הקיים, בלי שהשער תלוי בענן בזמן הכניסה.

The guest imports the link into the app; opening remains local over the existing secure BLE protocol, with no cloud dependency at entry time.

גבול חשוב: WIFIGATE Host אינו פותח שער דרך האינטרנט, אינו מחליף את SECURE_V3, ואינו עוקף את אימות inviterPhone + inviterEmail בקושחה.

Important boundary: WIFIGATE Host does not open a gate over the internet, replace SECURE_V3, or bypass firmware validation of inviterPhone + inviterEmail.

02 · End-to-end architecture

שני מישורים, ללא ערבוב credentials

Two planes, with no credential mixing

מישור הניהול מיועד לבני אדם; מישור האינטגרציה של WIFIGATE Host מיועד לשרתים. שניהם פוגשים backend אחד שמבצע הרשאה, אך משתמשים בזהויות שונות.

The management plane is for humans; the WIFIGATE Host integration plane is for servers. Both reach one authorization backend, but use different identities.

מישור פורטל

Portal plane

/login/ ו־/dashboard/. הדפדפן שולח Firebase ID token ל־Portal API. אין גישה ישירה ל־Firestore ואין Client API key ב־URL, ב־analytics או באחסון דפדפן.

/login/ and /dashboard/. The browser sends a Firebase ID token to the Portal API. There is no direct Firestore access and no Client API key in URLs, analytics or browser storage.

מישור אינטגרציה

Integration plane

POST /v1/guest-invitations. שרת השותף שולח Bearer key ו־JSON. אין Firebase token אנושי ואין קריאה מה־frontend של הלקוח.

POST /v1/guest-invitations. The partner server sends a Bearer key and JSON. No human Firebase token and no call from the partner frontend.

סדר העיבוד המחייב: authenticate Client API key → rate limit → validate body → idempotency → decrypt system value → validate target → check every system entitlement → build protocol payload → encrypt invite → meter → respond.

Required processing order: authenticate Client API key → rate limit → validate body → idempotency → decrypt system value → validate target → check every system entitlement → build protocol payload → encrypt invite → meter → respond.

03 · Invitation protocol alignment

אותו פרוטוקול שהאפליקציה כבר קוראת

The same protocol the app already reads

WIFIGATE Host אינו ממציא פורמט הזמנה שני. הוא מפיק את אותו ep מוצפן ואת אותם payloads קומפקטיים המוגדרים ב־README_WIFIGATE_LINK_INVITATIONS.md.

WIFIGATE Host does not invent a second invitation format. It emits the same encrypted ep and compact payloads defined by README_WIFIGATE_LINK_INVITATIONS.md.

דיוק הזמן בפרוטוקול: ה־backend יפיק epoch במילישניות. ה־mobile מקבל גם seconds וגם milliseconds, ואם se מסתיים בדיוק ב־HH:mm:00.000 הוא מנרמל את סוף החלון ל־HH:mm:59.999; לכן זמן checkout של 09:00 תקף עד סוף הדקה 09:00.

Protocol time precision: the backend emits epoch milliseconds. Mobile accepts seconds or milliseconds, and when se lands exactly on HH:mm:00.000 it normalizes the window end to HH:mm:59.999; a 09:00 checkout is therefore valid through the end of the 09:00 minute.

ייבוא אטומי של יעד מרובה שערים: שער אחד לא תקין, פג או לא מורשה מבטל את כל הייבוא של Dual Control או Group. שום שער חלקי אינו נשמר, ושום role קבוע אינו יורד ל־GUEST.

Atomic multi-gate import: one invalid, expired or unauthorized gate aborts the entire Dual Control or Group import. No partial gate is saved and no permanent role is downgraded to GUEST.

פער מימוש מזוהה: כיום buildGateGuestsApiKey ו־buildDualControlGuestsApiKey יוצרים מעטפות guests-api-key, אך אינם כוללים עדיין h/he/hn; אין עדיין builder מקביל ל־Group. לפני השקת WIFIGATE Host חייבים להשלים את שלושתם ולנעול golden vectors משותפים ל־mobile ול־backend.

Known implementation gap: today buildGateGuestsApiKey and buildDualControlGuestsApiKey create guests-api-key envelopes, but do not yet include h/he/hn; there is no equivalent Group builder yet. Before WIFIGATE Host launches, all three must be completed and locked with shared mobile/backend golden vectors.

אין לשים סודות בדוגמאות אמיתיות: psk, WIFIGATE Host KEY, Client API key ו־invite URL מלא הם credentials. הדוגמאות במסמך מכילות placeholders בלבד.

Never put secrets in real examples: psk, WIFIGATE Host KEYs, Client API keys and full invite URLs are credentials. This document uses placeholders only.

04 · WIFIGATE Host KEY

מה המפתח מכיל בכל סוג יעד

What the key contains for every target type

זהו חוזה היסוד שעליו נבנית WIFIGATE Host: מפתח מוצפן אחד מתאר בדיוק Gate,‏ Dual Control או Group, כולל הזהות, המבנה, הגדרות התצוגה וחומר ה־BLE הדרוש להפקת הזמנות אורח.

This is the foundational contract for WIFIGATE Host: one encrypted key describes exactly one Gate, Dual Control or Group, including identity, topology, display settings and the BLE material required to issue guest invitations.

חוזה בסיסFoundation contract

השם במוצר ובתיעוד: WIFIGATE Host KEY. לצורך backward compatibility, שם השדה ב־API נשאר encryptedKeyValue, ה־prefix נשאר wgk_live_, והסמן הפנימי המוצפן נשאר כרגע k="guests-api-key". השמות הטכניים אינם שם המוצר שמוצג למשתמש.

Product and documentation name: WIFIGATE Host KEY. For backward compatibility, the API field remains encryptedKeyValue, the prefix remains wgk_live_, and the encrypted internal marker remains k="guests-api-key" for now. These technical identifiers are not the user-facing product name.

כללי יצירה

Creation rules

  • רק Admin מקומי רשאי ליצור WIFIGATE Host KEY.
  • Only a local Admin may create a WIFIGATE Host KEY.
  • Dual דורש Admin בשני השערים.
  • Dual requires Admin on both gates.
  • Group דורש Admin והרשאת הזמנת אורחים בכל שער ישיר ובכל שער שבתוך Dual או קבוצת־בת.
  • Group requires Admin and guest-invitation permission on every direct gate and every gate inside a Dual or child group.
  • חוסר ב־h, he או בחבילת SECURE_V3 מלאה חוסם יצירה.
  • Missing h, he or a complete SECURE_V3 bundle blocks creation.

כללי snapshot

Snapshot rules

  • המפתח הוא snapshot קבוע, לא pointer חי לאפליקציה.
  • The key is an immutable snapshot, not a live pointer into the app.
  • שינוי שם, כתובת, שער או הרכב Group דורש מפתח חדש.
  • Changing a name, address, gate or Group composition requires a new key.
  • Group ריק, כפול, גדול מ־20 systems או גדול מ־12KB נחסם.
  • An empty, duplicate, over-20-system or over-12KB Group is rejected.
  • כל systemId ביעד חייב entitlement פעיל בזמן יצירת הזמנה.
  • Every systemId in the target needs an active entitlement when an invitation is created.

סיווג אבטחה: WIFIGATE Host KEY הוא credential סודי של המערכת, לא מזהה ציבורי. הוא מכיל pairingSecret, חומר BLE וזהות מזמין. שומרים אותו רק ב־server secret storage; לא בדפדפן, לא ב־Git, לא ב־URL, לא ב־analytics ולא בלוג.

Security classification: a WIFIGATE Host KEY is a secret system credential, not a public identifier. It contains pairingSecret, BLE material and inviter identity. Store it only in server-side secret storage — never in a browser, Git, URL, analytics or logs.

עדכון וביטול

Update and cancellation

שינוי תאריכים

Date change

השותף שולח version חדש עם Idempotency-Key חדש. הקישור החדש מחליף את הישן בתקשורת לאורח, אך הקישור הישן נשאר תקף בחלון המקורי.

The partner sends a new version with a new Idempotency-Key. The new link replaces the old one in guest communication, but the old link remains valid in its original window.

ביטול לפני מסירה

Cancellation before delivery

אין שולחים את הקישור. רשומת WIFIGATE Host עוברת ל־cancelled ואין יצירה נוספת.

Do not deliver the link. Mark the WIFIGATE Host record cancelled and do not create another invitation.

ביטול אחרי מסירה

Cancellation after delivery

ב־v1 אין ביטול ענני פרטני של קישור שכבר הגיע לטלפון, כי השער פועל offline. מצמצמים חלונות, מנפיקים סמוך להגעה ומציגים את המגבלה לצוות.

v1 cannot individually revoke a delivered link in the cloud because the gate works offline. Keep windows tight, issue near arrival and make the limitation visible to staff.

לא להבטיח revoke שאינו קיים: ביטול Client API key עוצר רק יצירת הזמנות חדשות. הוא אינו מבטל קישור קיים. הסרת זהות המזמין מהשער מבטלת קישורים קיימים של אותו מזמין — אך היא פעולה רחבה, לא ביטול של reservation יחיד.

Do not promise revocation that does not exist: revoking a Client API key only stops new invitations. It does not cancel an existing link. Removing the inviter identity from the gate invalidates that inviter's existing links — but it is a broad action, not single-reservation cancellation.

07 · Digital keys & credentials

שני מפתחות שונים, שתי מטרות שונות

Two different keys for two different purposes

ה־Client API key מזהה את האינטגרציה. ה־WIFIGATE Host KEY מגדיר את השערים ואת זהות המזמין. רק שילוב תקין של שניהם מאפשר יצירת קישור.

The Client API key identifies the integration. The WIFIGATE Host KEY defines gates and inviter identity. Only a valid combination can create a link.

Client API key

wfg_live_k_7H2M9Q4P8D.<256-bit-secret>

  • מונפק בשרת ל־client ול־ownerUid.
  • Server-issued to a client and ownerUid.
  • כולל scopes, target types, environment, rate limit ו־quota.
  • Carries scopes, target types, environment, rate limit and quota.
  • ניתן ל־rotation ול־revoke מיידי; revoked לעולם לא מופעל מחדש.
  • Supports rotation and immediate revoke; a revoked key is never reactivated.

WIFIGATE Host KEY

wgk_live_v1.<AES-GCM-envelope>

  • נוצר באפליקציה רק על ידי Admin מקומי מורשה.
  • Created in the app only by an authorized local Admin.
  • מכיל snapshot של Gate/Dual/Group, חומר BLE ו־h/he/hn.
  • Contains a Gate/Dual/Group snapshot, BLE material and h/he/hn.
  • אינו נשמר בפורטל ואינו מוצג בדוחות; ה־PMS שומר אותו כ־server secret.
  • Not stored in the portal or shown in reports; the PMS stores it as a server secret.

מה מותר לשמור באירוע שימוש

What a usage event may retain

מותר: requestId, clientId, apiKeyId, fingerprint חד־כיווני, target type/id, system IDs, status, outcome, latency ותאריך. אסור: Authorization header, הסוד המלא, encryptedKeyValue, inviteUrl, psk, שם/טלפון/אימייל אורח או body מלא.

Allowed: requestId, clientId, apiKeyId, one-way fingerprint, target type/id, system IDs, status, outcome, latency and timestamp. Forbidden: Authorization header, full secret, encryptedKeyValue, inviteUrl, psk, guest name/phone/email or full body.

הערת trust: סוד ההצפנה של invite links שנארז באפליקציית client אינו trust root. ההרשאה האמיתית נשענת על Client API key ו־entitlement בשרת, זהות אורח באפליקציה, pairing מאובטח, ואימות מקומי בקושחה.

Trust note: an invite-link encryption secret shipped in a client app is not a trust root. Real authorization relies on the server-side Client API key and entitlement, guest identity in the app, secure pairing and local firmware validation.
