Priority and load

  1.   2. P1 - admin mutation: שינויים קטנים אטומיים ו־factory reset commit.Small atomic changes and factory-reset commit.
  3. P2 - admin query: pages, overview, status ו־history.Pages, overview, status and history.
  4. P3 - bulk: import ו־FOTA. ניתנים להשהיה בין windows.Import and FOTA. Pausable between windows.

כלל preemption: bulk לעולם אינו מחזיק lock בזמן כתיבת flash. בכל window הקושחה מעבדת bounded bytes, משחררת ל־scheduler ומאפשרת ל־P0 להפסיק אנרגיה או לשחרר Push Button. פקודת OPEN בזמן SYSTEM_BLE_SERVER אינה עושה preempt אלא מקבלת BUSY; בזמן commit קצר שחוסם גם release, ה־UI חייב להציג זאת מראש והחלון חייב להישאר bounded.

Preemption rule: bulk never holds a lock while waiting on flash. Each window processes bounded bytes, yields to the scheduler and admits P0 de-energize or Push Button release. OPEN during SYSTEM_BLE_SERVER does not preempt; it receives BUSY. A short commit that also blocks release must be disclosed in advance and remain bounded.

פעולות הרסניות

Destructive operations

ADMIN_FACTORY_RESET_PREPARE מחזיר challenge אקראי, תיאור ההשפעה ו־expiresInMs ≤ 30,000. ה־commit חייב לכלול challenge, requestId חדש והקלדה/אישור native. challenge הוא חד־פעמי, קשור ל־session ול־systemId, ונמחק בכל disconnect.

ADMIN_FACTORY_RESET_PREPARE returns a random challenge, impact summary and expiresInMs ≤ 30,000. Commit must carry the challenge, a fresh requestId and native typed/explicit confirmation. The challenge is single-use, bound to session and systemId, and cleared on disconnect.

אסור להעתיק את מודל ה־Web. אין webAdminToken, cookie, bearer token, token ב־query, TTL של חמש שעות או secret שנשמר ב־AsyncStorage. ה־BLE session הוא ה־session.

Do not copy the Web model. There is no webAdminToken, cookie, bearer token, query token, five-hour TTL or secret in AsyncStorage. The BLE session is the session.

AAD   = bytes 0..19 || uint16BE(systemIdUtf8Length) || UTF8(systemId) || sessionId[8]
nonce = bulkNoncePrefix[8] || packetSeq[4]
key   = direction-specific HKDF-SHA256 key bound to transcriptHash, sessionId and transferId
  • packetSeq מתחיל ב־1 לכל transfer+session+direction ולעולם אינו חוזר בתחום הזה. reconnect יוצר session ומפתחות חדשים ומאפס seq.
  • packetSeq starts at 1 for each transfer, session and direction and never repeats in that scope. Reconnect creates new session keys and resets the sequence.
  • byteOffset מאפשר resume ואימות סדר ללא תלות במספר packets.
  • byteOffset enables resume and ordering independent of packet count.
  • ACK מפרסם את ה־next verified offset ואת מספר ה־credits. NACK מפרסם את ה־expected offset; retransmit משתמש ב־packetSeq חדש כדי לא למחזר nonce.
  • ACK advertises the next verified offset and available credits. NACK advertises the expected offset; retransmission uses a new packetSeq so a nonce is never reused.
  • CRC אינו מנגנון אבטחה ואינו נדרש בתוך packet; GCM מאמת כל packet, ו־SHA-256 מאמת artifact מלא.
  • CRC is not a security mechanism and is unnecessary inside a packet; GCM authenticates each packet and SHA-256 verifies the complete artifact.

כללי envelope

Envelope rules

  • requestId הוא UUID v4 ונדרש לכל mutation ולכל transfer begin/finish. query יכול לשלוח אותו לצורך tracing.
  • requestId is a UUID v4 required for every mutation and transfer begin/finish. Queries may send it for tracing.
  • expectedRevision מפעיל optimistic concurrency. mismatch מחזיר outer status ‏FAIL ו־admin.error.code=CONFLICT עם revision נוכחי, ללא כתיבה.
  • expectedRevision enables optimistic concurrency. A mismatch returns outer status FAIL and admin.error.code=CONFLICT with the current revision, without writing.
  • fields חסרים ו־null אינם זהים. חסר = ללא שינוי; null = מחיקה רק במקום שה־schema מתיר.
  • Missing fields and null differ. Missing means unchanged; null clears only where schema permits.
  • Unknown fields ו־unknown enum values מחזירים outer status ‏FAIL ו־admin.error.code=INVALID_ARGUMENT; אין silent ignore ב־mutation.
  • Unknown fields and enum values return outer status FAIL and admin.error.code=INVALID_ARGUMENT; mutations never silently ignore them.
  • כל שורת control מוצפנת, כולל LF, חייבת להיכנס בתקרת 2,048 bytes הקיימת. רשימה מקטינה page לפני ש־base64/envelope חורגים מהתקרה.
  • Every encrypted control line, including LF, must fit the existing 2,048-byte ceiling. A list shortens its page before base64 and envelope overhead cross that ceiling.

Idempotency

Idempotency

הקושחה שומרת cache מוגבל של requestId → payloadHash + result לכל Admin lease. שימוש חוזר עם אותו hash מחזיר אותה תוצאה; hash שונה מחזיר IDEMPOTENCY_MISMATCH. בנוסף, הפעולה עצמה חייבת להיות semantically idempotent: upsert לפי countryCode+localNumber, delete של רשומה חסרה הוא OK, event מזוהה לפי slot+revision, ו־bulk מזוהה לפי transferId+offset.

Firmware keeps a bounded requestId → payloadHash + result cache for each Admin lease. Reuse with the same hash returns the same result; a different hash returns IDEMPOTENCY_MISMATCH. The operation itself must also be semantically idempotent: upsert by countryCode plus localNumber, deleting a missing record is OK, an event is addressed by slot plus revision, and bulk data is identified by transferId plus offset.

Implementation rules

  1. Extract first. handlers קיימים קוראים זמנית ל־domain services החדשים. כך בודקים parity בלי שתי מימושי business logic.
  2. Extract first. Existing handlers temporarily call the new domain services. This proves parity without two business-logic implementations.
  3. Bounded memory. אין allocation לפי גודל קובץ/collection. documents קטנים, page buffers קבועים ו־streaming.
  4. Bounded memory. No allocation scales with file or collection size. Use small documents, fixed page buffers and streaming.
  5. Atomic persistence. validate → temp write → fsync/close → rename. revision עולה רק אחרי commit.
  6. Atomic persistence. Validate → temporary write → fsync/close → rename. Revision increments only after commit.
  7. Single policy table. command, required role, destructive flag, priority, bulk requirement ו־feature flag נמצאים ברשומה אחת.
  8. Single policy table. Command, required role, destructive flag, priority, bulk requirement and feature flag live in one record.
  9. No transport leakage. domain אינו מכיר JSON, GATT, HTTP, cookie או React Native.
  10. No transport leakage. Domain code knows nothing about JSON, GATT, HTTP, cookies or React Native.
  11. Watchdog-safe. loops מעל records או flash קוראים yield באופן bounded ונמדדים ב־HIL.
  12. Watchdog-safe. Record and flash loops yield in bounded intervals and are measured in HIL.

בלעדיות ובטיחות בזמן Admin mode

Exclusivity and safety during Admin mode

כדי לשמר את ההתנהגות הקיימת, בזמן SYSTEM_BLE_SERVER פקודות שמפעילות את השער (OPEN, OPEN_GUEST, PUSH_BUTTON_HOLD, TOGGLE_ON, TOGGLE_GUEST_ON) מחזירות BUSY עם הודעת Admin mode. פקודות שמפסיקות אנרגיה או משחררות מצב (PUSH_BUTTON_RELEASE, TOGGLE_OFF, TOGGLE_GUEST_OFF) נשארות זמינות מטעמי בטיחות. פעולת שער פיזית ו־logic מקומי נשארים באחריות ה־gate task.

De-energizing or release commands (PUSH_BUTTON_RELEASE, TOGGLE_OFF, TOGGLE_GUEST_OFF) remain available for safety. Physical gate operation and local logic remain owned by the gate task.

קידוד ו־framing של control

Control encoding and framing

  • כל הודעת control היא אובייקט JSON יחיד ב־UTF-8 ללא BOM, ללא CR, ומסתיימת ב־LF יחיד (0x0A). תקרת accumulator היא 2,048 bytes כולל LF.
  • Every control message is one UTF-8 JSON object without a BOM or CR and ends in one LF byte (0x0A). The accumulator ceiling is 2,048 bytes including LF.
  • מספרים הם JSON integers בטווח safe שמוגדר לכל שדה; NaN, Infinity, exponent ו־fraction אסורים. hex הוא lowercase ללא 0x; Base64 הוא RFC 4648 רגיל עם padding.
  • Numbers are JSON integers within each field's defined range; NaN, Infinity, exponent and fractions are forbidden. Hex is lowercase without 0x; Base64 is standard RFC 4648 with padding.
  • ct הוא ciphertext || 16-byte GCM tag בקידוד Base64. JSON key order אינו משמעותי לפענוח envelope, אך plaintext קנוני נדרש ל־command HMAC.
  • ct is ciphertext || 16-byte GCM tag encoded as Base64. JSON key order is irrelevant when parsing an envelope, but canonical plaintext is required for the command HMAC.
  • ה־client שולח control אל CONTROL_RX. firmware bridge מקבל אותו גם ב־legacy write ל־CONTROL_TX; final firmware מסיר כתיבה מ־TX.
  • The client writes control to CONTROL_RX. Bridge firmware also accepts it through the legacy write on CONTROL_TX; final firmware removes writes from TX.

Legacy optional input fields sid, alg and ts remain accepted for compatibility, but new encoders do not emit them.

  4. The Admin context binds connection handle, systemId, Admin phone plus email and pairing keyId. Every command reloads the Admin record; deletion or authorization change produces UNAUTHORIZED and closes the context.
  5. expectedSeq מתחיל ב־1. frame מאומת מקבל response באותו seq, ואז המספר עולה באחד גם אם תוצאת domain היא FAIL/BUSY. seq חסר, כפול או עתידי נדחה ללא dispatch.
  6. expectedSeq starts at 1. An authenticated frame receives a response with the same sequence, then the sequence increments even when the domain result is FAIL or BUSY. A missing, duplicate or future sequence is rejected without dispatch.
  7. ה־secure idle TTL הוא 30,000ms ומתגלגל אחרי כל frame מאומת. freshnessMs ב־Admin חייב להיות 15,000; הלקוח שולח ADMIN_PING אחרי 10,000ms ללא frame. Ping אינו מאריך את Admin idle lease של 300,000ms; פקודת משתמש או bulk progress מאומת כן.
  8. The secure idle TTL is 30,000ms and rolls after every authenticated frame. Admin freshnessMs must be 15,000; the client sends ADMIN_PING after 10,000ms without a frame. Ping does not extend the 300,000ms Admin idle lease; a user command or authenticated bulk progress does.
  9. secure hard TTL הוא 300,000ms. ב־280,000ms הלקוח עוצר bulk בגבול ACK ושולח client_hello חדש באותו connection. הקושחה מרשה rekey רק לבעל ה־Admin context, מחליפה keys באופן אטומי ושומרת את ה־lease, revisions, idempotency cache ו־staging.
  10. The secure hard TTL is 300,000ms. At 280,000ms the client pauses bulk at an ACK boundary and sends a fresh client_hello on the same connection. Firmware permits rekey only for the Admin-context owner, atomically replaces keys and retains the lease, revisions, idempotency cache and staging.
  11. disconnect מנקה keys ו־Admin context מיד. staging מאומת נשמר ל־600,000ms ומזוהה מחדש רק אחרי handshake ו־Admin authorization חדשים.
  12. Disconnect immediately clears keys and the Admin context. Verified staging remains for 600,000ms and can be resumed only after a fresh handshake and Admin authorization.
  13. כדי לשמר release בזמן Admin mode, ה־firmware מחזיק Admin slot אחד ו־one-shot SECURE_V3 slot אחד. ניסיון Admin נוסף מקבל BUSY; ה־slot הנוסף רשאי לבצע רק פקודות legacy, כאשר פקודות energize עדיין BUSY ו־release/de-energize מקבלות עדיפות.
  14. To preserve release behavior during Admin mode, firmware keeps one Admin slot and one one-shot SECURE_V3 slot. A second Admin attempt receives BUSY; the extra slot may run only legacy commands, with energizing commands still BUSY and release or de-energize commands prioritized.
